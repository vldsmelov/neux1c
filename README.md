# NE UX

Система бюджетного контроля и управления договорами для пилота ООО "Гладиолус".

На первом этапе система имитирует интеграцию с 1С через заменяемый слой mock-адаптера. Это позволяет показывать рабочие сценарии без доступной 1С и позже подключить реальный обмен без переписывания бизнес-логики.

## Запуск

```powershell
copy .env.example .env
docker compose up --build
```

Приложение:

- web: http://localhost:8000
- НСИ / Mock-1C: http://localhost:8000/nsi/
- healthcheck: http://localhost:8000/healthz/
- админка: http://localhost:8000/admin/

## Mock-1C

Первичная загрузка демо-данных выполняется внутри контейнера:

```powershell
docker compose exec web python manage.py sync_mock_1c
```

Команда загружает справочники, договоры, допсоглашения и факт оплат по счетам 50/51. Повторный запуск обновляет существующие записи и пишет статистику в журнал синхронизаций.

## Доступы

Роли и демо-пользователи создаются командой:

```powershell
docker compose exec web python manage.py setup_access_roles --with-users
```

Демо-пароль по умолчанию: `demo12345`.

Пользователи:

- `admin` - администратор, доступ в админку и ко всем разделам;
- `economist` - экономист, доступ к рабочему месту и НСИ;
- `manager` - руководитель, доступ к рабочему месту;
- `accountant` - бухгалтер, доступен только внешний контур оплаты договоров.

Роли используют группы Django и профиль пользователя. Журнал действий доступен в админке.

Внешний контур бухгалтера:

```text
http://localhost:8000/external/accounting/
```

При оплате договора создается документ внешней оплаты и две записи факта оплаты БДДС: БУ и НУ. Это имитирует работу в 1С:БП, хотя технически пока выполняется внутри пилотного приложения.

## Планирование и лимиты

Экран планирования:

```text
http://localhost:8000/planning/limits/
```

Экономист создает годовой план с разбивкой по 12 месяцам. Система проверяет равенство месячной и годовой суммы. Затем план отправляется на утверждение руководителю. Руководитель утверждает план из того же раздела.

Корректировка лимита создается от утвержденного плана, требует обязательную причину и новую помесячную разбивку. После утверждения корректировки базовый план получает новую сумму и следующую версию.

## Интерфейс

Основная UX-модель приближена к привычной логике 1С: левое меню разделов, верхние вкладки, рабочая область документа, командные панели и табличные части. Базовая палитра бело-сине-голубая.

Палитра настраивается в админке через модель `Настройки палитры интерфейса`. Активная настройка применяется ко всем страницам через CSS-переменные.

## Рабочий процесс git

- `main` - стабильная ветка.
- `develop` - интеграционная ветка.
- `feature/*` - отдельные итерации и функциональные блоки.

Каждая итерация должна завершаться проверяемым состоянием: контейнеры поднимаются, есть демо-данные или понятный сценарий проверки, изменения зафиксированы коммитом.

Удаленный репозиторий подключается после получения URL:

```powershell
git remote add origin <repo-url>
git push -u origin main
git push -u origin develop
```

## Текущая итерация

`feature/bootstrap-docker-django`:

- Django-приложение;
- PostgreSQL в Docker Compose;
- healthcheck;
- стартовая страница рабочего места;
- архитектурная заметка по симуляции 1С.

`feature/mock-1c-nsi`:

- модели НСИ;
- mock-адаптер 1С;
- команда загрузки демо-данных;
- экран проверки `/nsi/`.

`feature/one-c-inspired-ui`:

- общий 1С-подобный shell интерфейса;
- бело-сине-голубая палитра;
- настройка палитры через админку;
- переработанные страницы `/` и `/nsi/`.

`feature/access-control-rbac`:

- роли администратора, экономиста, руководителя и бухгалтера;
- запрет доступа бухгалтеров к рабочим страницам;
- команда настройки ролей и демо-пользователей;
- журнал действий.

`feature/external-accounting-payments`:

- внешний контур бухгалтера `/external/accounting/`;
- оплата договоров с единственным поставщиком;
- автоматическое создание факта БУ/НУ как имитация 1С:БП;
- редирект бухгалтера после входа во внешний контур.

`feature/planning-limits`:

- документ "План / лимит";
- 12 строк помесячной разбивки;
- статусы черновик / на утверждении / утвержден / закрыт;
- отправка экономистом и утверждение руководителем.

`feature/limit-adjustments`:

- документ корректировки лимита;
- связь с утвержденным базовым планом;
- обязательная причина корректировки;
- новая сумма и новая разбивка по месяцам;
- повышение версии базового плана после утверждения.

`feature/contracts-reservations`:

- реестр договоров и резервирование `/contracts/reservations/`;
- расчет резерва, оплаты и остатка по договору;
- связь с утвержденными лимитами и остаток лимита после резерва.

`feature/contracts-tree`:

- дерево договоров `/contracts/tree/`;
- иерархия: доходный договор -> договор поставщика -> допсоглашения;
- фильтры по контрагенту, договору и дате;
- суммы и остатки на каждом уровне с пересчетом в RUB.
