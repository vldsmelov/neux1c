# Руководство пользователя и Use Case по ролям

Актуальная версия инструкции для текущего UI (рядная компоновка экранов):
формы и фильтры расположены в верхних блоках, реестры и таблицы — ниже, на полную рабочую ширину.

Документ описывает работу в системе по ролям: `Администратор`, `Экономист`, `Руководитель`, `Бухгалтер`.

## 1. Роли и границы доступа

| Роль | Основные действия |
|---|---|
| Администратор | Настройка системы, обработка заявок на интеграцию, доступ ко всем разделам |
| Экономист | Планы/лимиты, заявки на оплату, корректировка факта, отчеты и шаблоны |
| Руководитель | Согласование/отклонение заявок, утверждение планов, контроль KPI |
| Бухгалтер | Только внешний контур оплаты договоров (имитация внешней 1С:БП) |

---

## 2. Как читать экран

Для большинства разделов действует единый UX-паттерн:
1. Верхняя строка: заголовок раздела и командная панель.
2. Верхние панели: форма создания/редактирования или фильтры.
3. Ниже: KPI-карточки.
4. Ниже: секционные блоки с подзаголовком и таблицей-реестром.

Это позволяет быстро вносить изменения и сразу видеть результат в таблице без переключения между колонками.
На длинных экранах блоки создания и корректировки сворачиваются/разворачиваются по заголовку, чтобы не терять реестр из виду.
На экранах `Факт оплат`, `Договоры` и `НСИ` фильтры и служебные сводки также вынесены в сворачиваемые блоки под основными таблицами.

На desktop в правом верхнем углу доступен переключатель плотности таблиц:
- `☰` — стандартная плотность;
- `≣` — компактная плотность для длинных реестров.

## 4. Экономист

### UC-ECO-01: Создание плана/лимита
**Предусловия:** пользователь вошел как `economist`.

**Шаги:**
1. В разделе `Планирование` в верхней форме задать период планирования.
2. Указать годовую сумму.
3. Нажать `Записать` в командной панели.
4. В таблице ниже отправить черновик на утверждение кнопкой `На утверждение`.

**Ожидаемый результат:** план создается в статусе `Черновик`, после отправки — `На утверждении`.

![UC-ECO-01](images/annotated/02_economist_planning_limits.png)

### UC-ECO-02: Создание заявки на оплату и отправка на согласование

**Шаги:**
1. В форме заявки выбрать тип.
2. Указать договор поставщика.
3. Заполнить назначение платежа.
4. Нажать `Записать`.
5. В реестре заявок (нижняя таблица) нажать `На согласование`.

**Ожидаемый результат:** заявка переходит из `Черновик` в `На согласовании`.

## 8. Контрольный чек-лист приемки (для обучения)

1. Экономист создает и отправляет заявку на оплату.
2. Руководитель согласует/отклоняет заявку с комментарием.
3. Бухгалтер проводит оплату во внешнем контуре.
4. Экономист видит отражение факта и при необходимости корректирует его.
5. Экономист сохраняет и повторно применяет шаблон отчета.

Если шаги выполняются по скриншотам и статусы меняются ожидаемо, пользовательская цепочка работает корректно.

## 9. Сценарии планирования

Сценарий — это «версия плана» (базовая, оптимистичная, пессимистичная, ваша своя). Все бюджеты и лимиты привязаны к сценарию. Базовый сценарий используется в план-факте по умолчанию.

### UC-SCN-01: Создать сценарий
**Шаги:**
1. Открыть `Планирование → Сценарии`.
2. Развернуть `Создать сценарий`.
3. Указать код (например, `Opt-2027`), название, компанию, тип, опционально галочку «Сделать базовым», описание.
4. Нажать `Создать сценарий`.

**Ожидаемый результат:** сценарий появляется в таблице, статус «В работе». Если поставлена галочка «Сделать базовым» — другие baseline-сценарии этой компании и года автоматически сбрасываются.

### UC-SCN-02: Скопировать сценарий с коэффициентом (what-if)
**Цель:** быстро завести альтернативную версию плана (например, «+15% ко всем лимитам»).

**Шаги:**
1. Открыть `Сценарии`, развернуть `Скопировать сценарий с коэффициентом`.
2. Выбрать исходный сценарий.
3. Ввести название нового, выбрать тип, указать коэффициент (`1.15`, `0.80` и т.п.).
4. Нажать `Скопировать × коэффициент`.

**Ожидаемый результат:** все approved-лимиты исходного сценария копируются в новый с умножением годовой и помесячных сумм; помесячная разбивка пересчитывается с учётом округления.

### UC-SCN-03: Назначить сценарий базовым
**Шаги:**
1. В строке нужного сценария нажать `Сделать базовым`.

**Ожидаемый результат:** сценарий помечен зелёным badge «базовый», предыдущий baseline сбрасывается. План-факт-отчёт по умолчанию переключается на этот сценарий.

### UC-SCN-04: Просмотр план-факта по конкретному сценарию
**Шаги:**
1. Открыть `Отчёты → План-факт БДДС`.
2. В фильтрах выбрать сценарий в селекторе «Сценарий планирования».
3. Применить.

**Ожидаемый результат:** в строках отчёта показываются только лимиты выбранного сценария; прогноз и сводки пересчитываются.

## 10. Конструктор шаблона плана и массовый импорт

### UC-TPL-01: Собрать CSV-шаблон под Excel
**Цель:** подготовить заготовку для заполнения плана в Excel.

**Шаги:**
1. Открыть `Планирование → Конструктор шаблона`.
2. (опц.) Выбрать целевой сценарий — нужно только чтобы подписать пример-строку.
3. Отметить нужные колонки (обязательные: ЦФО, Статья ДДС, Валюта, Годовая сумма; опциональные: 12 помесячных, согласующий, комментарий).
4. (опц.) Сузить список ЦФО и Статей multi-select-ом.
5. Выбрать валюту по умолчанию и логин согласующего.
6. Поставить галочку `Сгенерировать заготовки строк` — система соберёт все комбинации ЦФО × Статья как пустые строки.
7. Нажать `⬇ Скачать шаблон CSV`.

**Ожидаемый результат:** скачивается CSV (UTF-8 BOM, разделитель `;`), Excel открывает его корректно с кириллицей.

### UC-TPL-02: Загрузить заполненный шаблон в сценарий
**Шаги:**
1. Заполнить годовые суммы (и опционально помесячные) в Excel, сохранить как CSV.
2. Открыть `Планирование → Сценарии`, в строке целевого сценария нажать `⬆ Импорт лимитов`.
3. Выбрать файл.

**Ожидаемый результат:** лимиты создаются пакетно в этом сценарии; success-сообщение «создано N, ошибок M». При ошибке (например, неизвестный ЦФО) строка пропускается, остальные создаются.

### UC-TPL-03: Скачать шаблон с реальными кодами для отдельного сценария
**Шаги:**
1. На странице `Сценарии` в строке сценария нажать `⬇ Шаблон`.

**Ожидаемый результат:** скачивается CSV с заголовками и одной строкой-примером с реальными кодами НСИ и подписью «Пример строки · сценарий «…» · год · компания».

## 12. Кейсы финансирования

Кейс — единая сделка, в которой живут вместе:
- доходные договоры (откуда деньги придут);
- расходные (куда деньги уйдут);
- займы (если денег не хватает);
- факты оплат и поступлений.

На одной карточке видно: сколько пришло, сколько ушло, что должны заплатить, кому должны мы и хватает ли покрытия.

### UC-FUND-01: Создать кейс
**Сценарий:** мама-компания спустила ТЗ на закупку стройматериалов на 2 000 000 ₽.

**Шаги:**
1. Открыть `Финансирование → Кейсы`.
2. Развернуть `Создать новый кейс`.
3. Заполнить код (`FUND-2026-001`), название «Закупка стройматериалов по ТЗ материнской», компанию, описание.
4. Нажать `Создать кейс`.

**Ожидаемый результат:** открывается карточка кейса со статусом «В работе» и пустыми метриками.

### UC-FUND-02: Привязать договоры к кейсу
**Шаги:**
1. На карточке кейса развернуть `Привязать договор к кейсу`.
2. Выбрать договор из выпадающего списка (показаны свежие договоры без кейса).
3. Нажать `Привязать`.
4. Повторить для всех связанных договоров: доходный, расходный, заём.

**Ожидаемый результат:** договоры появляются в соответствующих секциях карточки (`Договор с покупателем`, `Договор с единственным поставщиком`, `Договор займа`).

### UC-FUND-03: Записать поступление по доходному (quick-action)
**Шаги:**
1. На карточке кейса в секции `Договор с покупателем` нажать `Записать поступление →` в строке доходного договора.
2. В popover-форме указать дату, сумму, статью ДДС (поступление).
3. Нажать `Записать`.

**Ожидаемый результат:** создаётся `PaymentFact` INFLOW, сальдо кейса мгновенно пересчитывается, в Хронологии появляется событие «Поступление».

### UC-FUND-04: Записать возврат займа (quick-action)
**Шаги:**
1. В секции `Договор займа (получен нами)` нажать `Записать возврат →` в строке займа.
2. В popover-форме указать дату, сумму всего, сумму процентов (часть от всей суммы), статью ДДС.
3. Нажать `Записать`.

**Ожидаемый результат:** факт создаётся, проценты и тело разделяются автоматически; если у займа есть график платежей — соответствующие строки графика помечаются как `paid`.

### UC-FUND-05: What-if симулятор
**Цель:** проиграть «если придёт N ₽ сегодня — что будет с сальдо».

**Шаги:**
1. На карточке кейса в фиолетовой панели `🔮 What-if: если придёт сегодня` ввести сумму.
2. Нажать `Пересчитать →`.

**Ожидаемый результат:** справа от формы показывается прогноз `+N ₽ → Доступно: X · Прогноз: Y` с зелёной/красной подсветкой. Состояние БД не меняется — это виртуальный расчёт.

### UC-FUND-06: Печатная PDF-форма
**Шаги:**
1. На карточке кейса нажать `🖨 Печать / PDF` в шапке.
2. На открывшейся странице нажать `🖨 Печать / сохранить в PDF` (или Ctrl+P).
3. В диалоге браузера выбрать «Сохранить как PDF» или отправить на принтер.

**Ожидаемый результат:** одностраничный отчёт без сайдбара, оптимизирован под A4 — со сводкой, договорами, хронологией.

### UC-FUND-07: Понять Risk Score
- В шапке карточки и на каждой карточке списка кейсов есть chip с числом 0–100 и цветом:
  - 🟢 **0** «Без рисков»
  - 🔵 **1–29** «Низкий риск»
  - 🟡 **30–59** «Средний риск»
  - 🔴 **60–100** «Высокий риск»
- Tooltip раскрывает причины: «Дефицит сальдо: X ₽ (Y баллов)», «Заём вернуть через N дн. (M баллов)».

### UC-FUND-08: Применить рекомендацию по статусу
- Если в шапке кейса появилась голубая панель `💡 Рекомендация: …` — это автоматическая подсказка от системы.
- Нажать `Применить →` → статус кейса меняется в один клик.

Логика рекомендаций:
- все обязательства закрыты + cash ≥ 0 → **closed**
- active + ждём поступление + cash в минусе → **waiting_for_inflow**
- waiting_for_inflow + поступление пришло → **active**

## 13. Договоры займа с процентами и аннуитетный график

### UC-LOAN-01: Завести договор займа
**Шаги:**
1. Открыть `Договоры → Реестр`.
2. Создать договор с типом `Договор займа (получен нами)` или `Договор займа (выдан нами)`.
3. Заполнить контрагента (кредитор), валюту, тело займа, процентную ставку % годовых, дату возврата (`maturity_date`).
4. Указать кейс финансирования.

**Ожидаемый результат:** договор появляется в реестре, в карточке кейса — в секции займов.

### UC-LOAN-02: Сгенерировать аннуитетный график
**Шаги:**
1. На карточке кейса в строке займа найти форму `Периодов: [12] Сгенерировать график →`.
2. Указать число периодов (обычно равно числу месяцев между подписанием и maturity_date).
3. Нажать `Сгенерировать график →`.

**Ожидаемый результат:** под строкой займа раскрывается таблица «📅 График платежей (N периодов)»:
- Постоянный платёж (PMT) — рассчитан по аннуитету
- Тело растёт от первого к последнему периоду, проценты падают
- Остаток на последнем периоде = 0
- Просроченные строки (дата в прошлом, без оплаты) подсвечиваются красным

### UC-LOAN-03: Автоматическое закрытие строк графика
**Шаги:**
1. Записать возврат займа через `Записать возврат →` (UC-FUND-04).

**Ожидаемый результат:** строки графика автоматически помечаются `paid` начиная с самой ранней; внутри строки сначала закрываются проценты, потом тело. Success-сообщение «закрыто строк графика: N».

### UC-LOAN-04: Дайджест приближающихся сроков возврата
Системная команда (запускается планировщиком раз в день):
```
docker compose exec web python manage.py notify_loan_maturity --days 7
```
Шлёт owner-у каждого активного кейса уведомление о займах с `maturity_date` через ≤ N дней.

## 15. Отчёты для финансового контроля

### UC-RPT-01: План-факт БДДС с прогнозом
**Шаги:**
1. Открыть `Отчёты → План-факт БДДС`.
2. Настроить фильтры: год, организация, статья (можно группу — поддерево подтянется), сценарий, направление, кейс финансирования.
3. Применить.
4. Перейти на вкладку `Сводка`.

**Ожидаемый результат:** в `Сводке` — обычные итоги + новые карточки:
- **Прогноз исполнения БУ к концу года** = факт-to-date + (план+корр) × (12 − cutoff_month) / 12
- **Отклонение прогноза от плана+корр.** с зелёной (экономия) или красной (перерасход) подсветкой

### UC-RPT-02: БДР (доходы / расходы по начислению)
**Шаги:**
1. Открыть `Отчёты → БДР · Доходы и расходы`.
2. Выбрать год и (опц.) организацию или кейс.

**Ожидаемый результат:** три headline-плашки:
- **Доходы начислены** (сумма CUSTOMER-договоров за год)
- **Расходы начислены** (SUPPLIER-договоры)
- **Прибыль или Убыток** с маржой %

Ниже секция «Дельта начислено vs кассой»: получено фактом / уплачено фактом / дебиторская задолженность / кредиторская задолженность / чистый денежный поток.

### UC-RPT-03: Дашборд CFO
**Шаги:**
1. Открыть `Отчёты → CFO дашборд`.
2. Выбрать год и компанию (пусто = весь холдинг).

**Ожидаемый результат:** 5 KPI-плашек верхнего уровня:
- 💵 Cash position YTD
- 📊 Прибыль по начислению YTD
- 💼 Кейсы (в дефиците из активных)
- 🏦 Займы к возврату
- ⏱ Просроченные заявки

Ниже:
- 📈 SVG-чарт тренда cash position по месяцам
- 🚨 Топ-риски — кликабельный список самых проблемных позиций

### UC-RPT-04: Дашборд руководителя с финансированием
**Шаги:**
1. Открыть `Отчёты → Руководителю`.

**Ожидаемый результат:** обычный дашборд + блок **«Финансирование: внимание»** с:
- Топ кейсов с дефицитом (со ссылками)
- Ближайшие сроки возврата займов (30-дневный горизонт)

## 17. Two-stage approval больших платежей

Если на компании настроены поля `escalation_threshold_rub` и `secondary_approver` (в админке или через shell), то крупные заявки автоматически уходят на двухэтапное согласование.

### UC-2STAGE-01: Эскалация по сумме
**Шаги (происходит автоматически):**
1. Экономист создаёт заявку на оплату суммой выше порога.
2. Отправляет на согласование как обычно.
3. Первый approver (manager) согласует.

**Ожидаемый результат:** заявка не уходит сразу в статус `Согласована` — она переходит в новый статус `На финальном согласовании`, `approver` меняется на `secondary_approver`, ему приходит уведомление. Только финальное одобрение делает заявку `Согласованной`.
