# Руководство пользователя и Use Case по ролям

Документ описывает работу в системе по ролям: `Администратор`, `Экономист`, `Руководитель`, `Бухгалтер`.
Для каждого сценария указаны действия и ожидаемый результат.

## 1. Роли и границы доступа

| Роль | Основные действия |
|---|---|
| Администратор | Настройка системы, обработка заявок на интеграцию, доступ ко всем разделам |
| Экономист | Планы/лимиты, заявки на оплату, корректировка факта, отчеты и шаблоны |
| Руководитель | Согласование/отклонение заявок, утверждение планов, контроль KPI |
| Бухгалтер | Только внешний контур оплаты договоров (имитация внешней 1С:БП) |

---

## 2. Общий сценарий входа (все роли)

### UC-LOGIN-01: Вход в систему
**Цель:** авторизоваться под своей ролью.

**Шаги:**
1. Ввести логин роли.
2. Ввести пароль.
3. Нажать `Войти`.

**Ожидаемый результат:** открывается рабочий контур роли (для бухгалтера — сразу внешний контур оплаты).

![UC-LOGIN-01](images/annotated/01_login.png)

## 3. Экономист

### UC-ECO-01: Создание плана/лимита
**Предусловия:** пользователь вошел как `economist`.

**Шаги:**
1. В разделе `Планирование` задать период.
2. Указать годовую сумму.
3. Нажать `Записать`.
4. Для отправки на утверждение нажать `На утверждение` в строке черновика.

**Ожидаемый результат:** план создается в статусе `Черновик`, после отправки — `На утверждении`.

![UC-ECO-01](images/annotated/02_economist_planning_limits.png)

### UC-ECO-02: Создание заявки на оплату и отправка на согласование
**Предусловия:** есть договор поставщика.

**Шаги:**
1. Выбрать тип заявки.
2. Указать договор.
3. Заполнить назначение платежа.
4. Нажать `Записать`.
5. В таблице нажать `На согласование`.

**Ожидаемый результат:** заявка переходит из `Черновик` в `На согласовании`.

![UC-ECO-02](images/annotated/03_economist_payment_requests.png)

### UC-ECO-03: Корректировка факта оплаты (БУ/НУ)
**Шаги:**
1. В строке факта изменить сумму.
2. Указать причину изменения.
3. Нажать `Записать`.

**Ожидаемый результат:** создается новая версия корректировки, изменения отражаются в факте и в аудите.

![UC-ECO-03](images/annotated/06_economist_payment_facts_adjust.png)

### UC-ECO-04: Работа с шаблонами отчета План-факт
**Шаги:**
1. Настроить фильтры отчета.
2. Ввести имя шаблона.
3. Нажать `Сохранить шаблон`.
4. Выбрать сохраненный шаблон.
5. Нажать `Применить шаблон`.

**Ожидаемый результат:** фильтры сохраняются как персональный шаблон экономиста и повторно применяются одним действием.

![UC-ECO-04](images/annotated/07_economist_report_templates.png)

## 4. Руководитель

### UC-MGR-01: Согласование или отклонение заявки
**Шаги:**
1. Нажать `Согласовать` для заявки в статусе `На согласовании`.
2. Для отклонения ввести комментарий причины.
3. Нажать `Отклонить` при необходимости.

**Ожидаемый результат:** заявка получает статус `Согласована` или `Отклонена`, комментарий фиксируется в карточке и в журнале.

![UC-MGR-01](images/annotated/04_manager_payment_approval.png)

### UC-MGR-02: Утверждение плана/корректировки лимита
**Шаги:**
1. Открыть раздел `Планирование`.
2. В строке документа со статусом `На утверждении` нажать `Утвердить`.

**Ожидаемый результат:** документ получает статус `Утвержден`.

![UC-MGR-02](images/annotated/05_manager_plan_approval.png)

### UC-MGR-03: Контроль на дашборде
**Шаги:**
1. Открыть `Дашборд руководителя`.
2. Проверить KPI в верхнем блоке.
3. Просмотреть статьи/позиции с риском перерасхода.

**Ожидаемый результат:** руководитель видит актуальную картину по лимитам, факту и статусам заявок.

![UC-MGR-03](images/annotated/08_manager_dashboard.png)

## 5. Бухгалтер (внешний контур)

### UC-ACC-01: Оплата договора во внешней системе
**Предусловия:** пользователь вошел как `accountant`.

**Шаги:**
1. В строке договора указать сумму оплаты.
2. Нажать `Оплатить`.

**Ожидаемый результат:** платеж проводится во внешнем контуре, в основной системе появляется факт оплаты (БУ/НУ) через mock-интеграцию.

![UC-ACC-01](images/annotated/09_accountant_external_system.png)

## 6. Администратор

### UC-ADM-01: Регистрация запроса на интеграцию
**Шаги:**
1. Заполнить название интеграции.
2. Указать целевую систему.
3. Описать задачу.
4. Нажать `Создать заявку`.

**Ожидаемый результат:** создается карточка запроса на интеграцию.

### UC-ADM-02: Обработка запроса на интеграцию
**Шаги:**
1. В строке заявки выбрать новый статус.
2. Нажать `Сохранить`.

**Ожидаемый результат:** статус и комментарий администратора обновлены, заявка двигается по жизненному циклу.

![UC-ADM-01/02](images/annotated/10_admin_integration_requests.png)

---

## 7. Контрольный чек-лист приемки (для обучения)

1. Экономист создает и отправляет заявку на оплату.
2. Руководитель согласует/отклоняет с комментарием.
3. Бухгалтер проводит оплату во внешнем контуре.
4. Экономист видит отражение факта и при необходимости корректирует его.
5. Экономист сохраняет шаблон отчета и повторно применяет.

Если все шаги выполняются по скриншотам выше и статусы меняются ожидаемо — пользовательская цепочка работает корректно.
