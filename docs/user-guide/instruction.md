# Руководство пользователя и Use Case по ролям

Актуальная версия инструкции для текущего UI (рядная компоновка экранов):
формы и фильтры расположены в верхних блоках, реестры и таблицы — ниже, на полную рабочую ширину.

Документ описывает работу в системе по ролям: `Администратор`, `Экономист`, `Руководитель`, `Бухгалтер`.

## 1. Роли и границы доступа

| Роль | Основные действия |
|---|---|
| Администратор | Настройка системы, обработка заявок на интеграцию, доступ ко всем разделам |
| Экономист | Планы/лимиты, заявки на оплату, корректировка факта, отчеты и шаблоны |
| Руководитель | Согласование/отклонение заявок, утверждение планов, контроль KPI |
| Бухгалтер | Только внешний контур оплаты договоров (имитация внешней 1С:БП) |

---

## 2. Как читать экран

Для большинства разделов действует единый UX-паттерн:
1. Верхняя строка: заголовок раздела и командная панель.
2. Верхние панели: форма создания/редактирования или фильтры.
3. Ниже: KPI-карточки.
4. Ниже: секционные блоки с подзаголовком и таблицей-реестром.

Это позволяет быстро вносить изменения и сразу видеть результат в таблице без переключения между колонками.
На длинных экранах блоки создания и корректировки сворачиваются/разворачиваются по заголовку, чтобы не терять реестр из виду.
На экранах `Факт оплат`, `Договоры` и `НСИ` фильтры и служебные сводки также вынесены в сворачиваемые блоки под основными таблицами.

На desktop в правом верхнем углу доступен переключатель плотности таблиц:
- `☰` — стандартная плотность;
- `≣` — компактная плотность для длинных реестров.

## 3. Общий сценарий входа (все роли)

### UC-LOGIN-01: Вход в систему
**Цель:** авторизоваться под своей ролью.

**Шаги:**
1. Ввести логин роли.
2. Ввести пароль.
3. Нажать `Войти`.

**Ожидаемый результат:** открывается рабочий контур роли (для бухгалтера — сразу внешний контур оплаты).

## 4. Экономист

### UC-ECO-01: Создание плана/лимита
**Предусловия:** пользователь вошел как `economist`.

**Шаги:**
1. В разделе `Планирование` в верхней форме задать период планирования.
2. Указать годовую сумму.
3. Нажать `Записать` в командной панели.
4. В таблице ниже отправить черновик на утверждение кнопкой `На утверждение`.

**Ожидаемый результат:** план создается в статусе `Черновик`, после отправки — `На утверждении`.

![UC-ECO-01](images/annotated/02_economist_planning_limits.png)

### UC-ECO-02: Создание заявки на оплату и отправка на согласование
**Предусловия:** есть договор поставщика.

**Шаги:**
1. В форме заявки выбрать тип.
2. Указать договор поставщика.
3. Заполнить назначение платежа.
4. Нажать `Записать`.
5. В реестре заявок (нижняя таблица) нажать `На согласование`.

**Ожидаемый результат:** заявка переходит из `Черновик` в `На согласовании`.

![UC-ECO-02](images/annotated/03_economist_payment_requests.png)

### UC-ECO-03: Корректировка факта оплаты (БУ/НУ)
**Шаги:**
1. В верхней панели выбрать фильтры периода и учета.
2. В таблице факта изменить сумму по строке.
3. Указать причину корректировки.
4. Нажать `Записать`.

**Ожидаемый результат:** создается новая версия корректировки; изменения отражаются в факте и в аудите.

![UC-ECO-03](images/annotated/06_economist_payment_facts_adjust.png)

### UC-ECO-04: Работа с шаблонами отчета План-факт
**Шаги:**
1. Настроить фильтры в верхней панели отчета.
2. При необходимости раскрыть блок `Шаблоны отчета`.
3. Ввести имя шаблона.
4. Нажать `Сохранить шаблон`.
5. Выбрать сохраненный шаблон.
6. Нажать `Применить`.

**Ожидаемый результат:** фильтры сохраняются как персональный шаблон экономиста и повторно применяются одним действием.

![UC-ECO-04](images/annotated/07_economist_report_templates.png)

## 5. Руководитель

### UC-MGR-01: Согласование или отклонение заявки
**Шаги:**
1. Открыть `Заявки на оплату`.
2. В таблице нажать `Согласовать` для заявки в статусе `На согласовании`.
3. Для отклонения ввести комментарий и нажать `Отклонить`.

**Ожидаемый результат:** заявка получает статус `Согласована` или `Отклонена`, комментарий фиксируется в карточке и журнале.

![UC-MGR-01](images/annotated/04_manager_payment_approval.png)

### UC-MGR-02: Утверждение плана/корректировки лимита
**Шаги:**
1. Открыть раздел `Планирование`.
2. В реестре документов со статусом `На утверждении` нажать `Утвердить`.

**Ожидаемый результат:** документ получает статус `Утвержден`.

![UC-MGR-02](images/annotated/05_manager_plan_approval.png)

### UC-MGR-03: Контроль на дашборде
**Шаги:**
1. Открыть `Дашборд руководителя`.
2. Проверить KPI в верхнем блоке.
3. Ниже просмотреть таблицы по остаткам, превышениям и статусам заявок.

**Ожидаемый результат:** руководитель видит актуальную картину по лимитам, факту и статусам заявок.

![UC-MGR-03](images/annotated/08_manager_dashboard.png)

## 6. Бухгалтер (внешний контур)

### UC-ACC-01: Оплата договора во внешней системе
**Предусловия:** пользователь вошел как `accountant`.

**Шаги:**
1. Открыть `Внешняя 1С:БП`.
2. В строке договора указать сумму оплаты.
3. Нажать `Оплатить`.

**Ожидаемый результат:** платеж проводится во внешнем контуре, в основной системе появляется факт оплаты (БУ/НУ) через mock-интеграцию.

![UC-ACC-01](images/annotated/09_accountant_external_system.png)

## 7. Администратор

### UC-ADM-01: Регистрация запроса на интеграцию
**Шаги:**
1. В верхней форме заполнить название интеграции.
2. Указать целевую систему.
3. Описать задачу.
4. Нажать `Создать заявку`.

**Ожидаемый результат:** создается карточка запроса на интеграцию в реестре ниже.

### UC-ADM-02: Обработка запроса на интеграцию
**Шаги:**
1. В таблице заявки выбрать новый статус.
2. При необходимости добавить комментарий администратора.
3. Нажать `Сохранить`.

**Ожидаемый результат:** статус и комментарий обновлены, заявка двигается по жизненному циклу.

![UC-ADM-01/02](images/annotated/10_admin_integration_requests.png)

## 8. Контрольный чек-лист приемки (для обучения)

1. Экономист создает и отправляет заявку на оплату.
2. Руководитель согласует/отклоняет заявку с комментарием.
3. Бухгалтер проводит оплату во внешнем контуре.
4. Экономист видит отражение факта и при необходимости корректирует его.
5. Экономист сохраняет и повторно применяет шаблон отчета.

Если шаги выполняются по скриншотам и статусы меняются ожидаемо, пользовательская цепочка работает корректно.
