# План итерационной разработки

Проект ведется короткими завершенными итерациями. Каждая итерация должна иметь проверяемый результат в Docker Compose и отдельную git-ветку `feature/*`.

## Git-процесс

- `main` - стабильная версия, готовая к демонстрации.
- `develop` - интеграционная ветка.
- `feature/*` - разработка конкретной итерации.
- `fix/*` - исправления дефектов.
- `release/*` - подготовка пилотного релиза.

Удаленный репозиторий подключается после передачи URL. До этого история ведется локально.

## Итерции

### 0. Инфраструктура

Результат:

- git-репозиторий;
- Docker Compose;
- Django-приложение;
- PostgreSQL;
- healthcheck;
- стартовая страница рабочего места.

Проверка:

```powershell
docker compose up --build
curl.exe http://127.0.0.1:8000/healthz/
```

### 1. Mock-1C и НСИ

Результат:

- контракт интеграции с 1С;
- mock-адаптер;
- справочники статей ДДС, контрагентов, номенклатуры, договоров и допсоглашений;
- первичная загрузка демо-данных ООО "Гладиолус".

Проверка:

- данные загружаются из mock-источника;
- объекты помечаются как синхронизированные с 1С или созданные вручную;
- статьи ДДС, отсутствующие в 1С, визуально выделяются.

### 1.1. UX, близкий к логике 1С

Результат:

- левое меню разделов;
- верхние вкладки открытых форм;
- рабочая область в формате документа;
- командные панели и табличные части;
- бело-сине-голубая палитра;
- настройка палитры через админку.

Проверка:

- `/` и `/nsi/` используют единый shell;
- палитра меняется через активную запись в админке;
- интерфейс остается читаемым на desktop и mobile.

### 2. Пользователи и права

Результат:

- роли администратора, экономиста и руководителя;
- явная роль бухгалтера без доступа к рабочим страницам основной системы;
- внешний контур бухгалтера для оплаты договоров;
- ручное создание пользователей;
- базовая RBAC-модель;
- запрет доступа для бухгалтеров;
- журнал действий.

Проверка:

- экономист работает с планами и фактами;
- руководитель утверждает и смотрит дашборды;
- администратор управляет пользователями;
- пользователь без роли не попадает в систему.
- бухгалтер входит в учетную запись, получает отказ доступа к рабочим страницам и может работать только во внешнем контуре оплат.

### 3. Планирование и лимиты

Результат:

- документ "План / лимит";
- годовой план с разбивкой по месяцам;
- горизонт планирования до 3 лет;
- статусы и утверждение руководителем;
- версия документа.

Проверка:

- сумма месяцев равна годовой сумме;
- утвержденный план участвует в расчете остатка лимита.

### 4. Корректировки лимитов

Результат:

- документ корректировки лимита;
- связь с базовым утвержденным планом;
- обязательная причина корректировки;
- история версий.

Проверка:

- корректировка отображается отдельно от исходного плана;
- отчет учитывает актуальную версию.

### 5. Договоры и резервирование

Результат:

- доходные договоры;
- договоры с единственным поставщиком;
- допсоглашения;
- ручной курс валют по договору;
- расчет резерва по договору и допсоглашениям.

Проверка:

- резерв уменьшает остаток лимита;
- сумма резерва видна в план-фактном отчете.

### 6. Дерево договоров

Результат:

- иерархия доходный договор -> договор поставщика -> допсоглашения;
- суммы и остатки на каждом уровне;
- фильтры по контрагенту, договору и дате.

Проверка:

- дерево отображает иерархию;
- фильтры работают;
- остатки пересчитываются корректно.

### 7. Заявки на оплату

Результат:

- заявки по договору, по счету, без договора;
- проверка остатка лимита;
- режим предупреждения или блокировки превышения;
- согласование;
- mock-передача в 1С:ДО.

Проверка:

- заявка в лимите создается;
- превышение подсвечивается или блокируется;
- согласованная заявка получает статус передачи в 1С.

### 8. Факт оплат БДДС

Результат:

- загрузка mock-факта по счетам 50 и 51;
- параллельный учет БУ и НУ;
- ручная корректировка экономистом;
- версии корректировок;
- учет закрытия месяца.

Проверка:

- факт отображается в БУ и НУ;
- корректировка сохраняет версию;
- закрытый месяц защищен от правок.

### 9. План-факт БДДС

Результат:

- отчет по макету ТЗ;
- расчет остатка;
- комментарии;
- выделение превышений, отсутствующих статей ДДС и ВГО;
- экспорт в Excel.

Проверка:

- отчет сходится на демо-данных;
- Excel содержит показатели и комментарии.

### 10. Дашборд руководителя

Результат:

- остатки лимитов;
- топ превышений;
- статусы заявок;
- фильтры;
- светлая и темная тема.

Проверка:

- показатели совпадают с план-фактным отчетом;
- руководитель видит только доступные данные.

### 11. Администрирование и интеграции

Результат:

- настройки интеграции с 1С только для администратора;
- заявки экономиста на настройку интеграции;
- журнал ошибок синхронизации;
- общие настройки системы.
- расширенные настройки интерфейса и палитр.

Проверка:

- экономист не меняет интеграцию;
- администратор обрабатывает заявки;
- ошибки mock-синхронизации логируются.

### 12. Пилотная приемка

Результат:

- seed-данные ООО "Гладиолус";
- smoke-тесты;
- инструкция запуска;
- тег пилотного релиза.

Проверка:

- все критерии приемки из ТЗ проходят на mock-данных.
