# Симуляция 1С на пилотном этапе

В пилоте реальная 1С недоступна, но система должна демонстрировать функциональность так, будто обмен уже существует. Поэтому интеграция проектируется как заменяемый слой.

## Подход

Бизнес-логика не обращается напрямую к 1С. Она работает с абстрактным поставщиком данных:

- `OneCProvider` - контракт интеграции;
- `MockOneCProvider` - реализация для пилота;
- `RealOneCProvider` - будущая реализация для реальной 1С.

Текущая реализация находится в:

- `core/integrations/one_c/provider.py`;
- `core/integrations/one_c/mock.py`;
- `core/services/one_c_sync.py`;
- `core/management/commands/sync_mock_1c.py`.

Проверочный интерфейс доступен по адресу `/nsi/`.

## Данные mock-адаптера

На первом этапе mock-адаптер должен отдавать:

- статьи ДДС;
- контрагентов;
- номенклатуру;
- договоры с покупателем;
- договоры с единственным поставщиком;
- допсоглашения;
- факт оплат по счетам 50 и 51;
- признак ВГО;
- признак наличия статьи ДДС в 1С.

## Приемочное правило

Каждая функция, зависящая от 1С, должна быть проверяема на mock-данных:

- синхронизация справочников;
- расчет резервирования;
- проверка лимита заявки;
- отображение факта БУ и НУ;
- выделение ВГО;
- экспорт план-фактного отчета.
