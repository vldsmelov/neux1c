📖 Как это работает

Сценарий: цепочка «Платежи > 1M ₽» с этапами Manager → CFO → CEO.

  1. Экономист создаёт заявку на 1 500 000 ₽ и отправляет на согласование.
  2. Система ищет applicable chain → находит «Платежи > 1M ₽».
  3. Заявка получает approver = manager, статус = pending_approval.
  4. Manager согласует → переход на следующий stage. approver = cfo.
  5. CFO согласует → переход на CEO. approver = ceo.
  6. CEO согласует → это был последний stage → статус = approved.
  7. На любом этапе reject → статус сразу rejected.

Backward compatibility: если для документа не нашлась цепочка — используется существующая 2-stage логика (escalation_threshold_rub + secondary_approver на организации).
